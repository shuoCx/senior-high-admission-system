# 软件系统开发课程设计 · 项目规划书

**简化广州中考公办高中录取模拟系统 —— 人员分工与交付方案**

项目组（8 人）· 组长：陈晓烁 · 2026 年 11 月 18 日

---

## 一、项目概览

| 项目 | 内容 |
|---|---|
| 课题 | 简化广州中考公办高中录取模拟系统 |
| 技术栈 | Spring Boot 3 + MySQL 8 + MyBatis-Plus + Vue3 + Element Plus |
| 部署方式 | 本地可复现部署：init.sql + 一键启动脚本 + 部署说明文档，不上线 |
| 团队规模 | 8 人（1 设计 + 3 后端 + 1 前端 + 3 测试） |
| 课程时间 | 第 14/15/16 周周二 13:50-17:20；第 17 周周一周二 8:30-17:20 |

**人员配置解释**：业务与录取正确性 35% ＋ 测试与验证 25% ＝ 60%。因此引擎线（后端）与测试线获得较多人力配置；界面与技术框架只占 15%，前端按一人配置。

| 评分项 | 权重 | 对应人力 |
|---|---|---|
| 业务与录取正确性 | 35% | A（设计）＋B（引擎） |
| 测试与验证 | 25% | E＋F＋H（三人测试线） |
| 需求建模与系统设计 | 15% | A（ER 图、伪代码、契约）＋C |
| 功能完成与运行质量 | 15% | C＋G＋D＋全员 |
| 协作与报告检查 | 10% | A 统筹＋全员 Git 记录与个人说明 |

## 二、分工总则

1. **各尽其职**：后端三个模块（引擎 / 落库一致性 / 业务接口）各一人。
2. **预期先行**：人工推演必须先于引擎编码完成并封版打 tag，不得用系统输出反充人工预期。
3. **主编制设计**：各模块方案由负责人起草、组长 48 小时内评审定稿；规则疑问一律沉淀 FAQ 文档。
4. **二次分工防闲置**：课程中后期人员按时间线转移职责（见第五节），无人空转。
5. **人人答辩**：每位成员须能解释负责模块与关键规则（任务书演示要求）。

## 六、协作规范与边界契约

### 6.1 三条接口边界（防甩锅）

| 契约 | 分界 | 作用 |
|---|---|---|
| StateWriter 接口 | B 调用 / C 实现 | 引擎算错归 B、落库错归 C，看接口两侧定位 |
| 投档日志表 | C 写入 / G 只读 | 解释类查询一律走日志表，G 不得自行推算 |
| REST 契约 | A 冻结 / D 依赖 | D 基于 mock 并行开发；改动契约须全组知会 |

### 6.2 互备结对

B↔C（引擎）；C↔G（后端）；E↔H（推演方法）；F↔E（测试）；D↔H（简单页面）；G↔A（部署兜底）。一人缺席，结对另一人可顶上。

### 6.3 Git 协作要求

- **分支策略**：`main ← feature/模块名-开发者`。
- **Commit 规范**：`feat|fix|test|docs|chore(模块): 描述`，禁止一次性巨型提交。
- **硬规则**：引擎（B）与数据层（C）的 PR 必须双人评审（A 必审），其余单人评审。
- 每个课程日末打 tag（`w14`、`w15`、`w16`、`v1.0`）。
- 报告章节包干到人，A 统稿；个人工作说明各自撰写。

## 八、阶段 0 说明

阶段 0 指从现在到第 14 周开课前的课外时间。为什么需要阶段 0，原因有二：

**1. 时间不足**

课内可用时间合计约 20 小时/人（第 14/15/16 周二各 3.5 小时、第 17 周周一一个全天、第 17 周周二以答辩为主）。

**2. 八个人并行协作，必须先有共同蓝图**

协作的前提是接口对齐：REST 契约让前端不等后端（mock 并行）、人工推演让测试不等引擎、StateWriter 契约让引擎与数据层互不阻塞。这些都是阶段 0 的产物——没有它们，所有人的工作变成串行依赖，有的人在课程设计课上就需要等待他人做完才能开始行动。所以为了确保大家能同时进行，这些规划需要提前做好。

**工作量预期**：除测试线（E/H 的人工推演较重）外，多数角色的阶段 0 投入在 1–2 天量级。
