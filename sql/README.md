# 数据库脚本目录

组内协商确定表结构后，脚本按以下顺序命名存放（数字前缀决定执行顺序）：

| 文件 | 内容 |
|---|---|
| `01-schema.sql` | 建库 `admission_db` + 建表 + 索引 |
| `02-init-data.sql` | 字典数据（梯度线、控制线、批次） |
| `03-sample-data.sql` | 模拟数据（高中、初中、学生、志愿） |

## 建议的表清单（依据《设计讨论提示》）

| 表名 | 说明 | 冗余列要求 |
|---|---|---|
| `school` | 高中 | 招生批次 |
| `junior_school` | 初中 | — |
| `student` | 学生 | **是否已录取、录取批次、录取学校**（实时更新） |
| `student_choice` | 志愿 | 学生 + 批次 + 志愿序号 + 高中 |
| `plan_batch1` | 第一批计划 | 高中、初始计划、已录取数、**计划余额** |
| `plan_batch2` | 第二批计划 | 高中 + 初中、初始计划、已录取数、**计划余额** |
| `plan_batch3` | 第三批计划 | 初始计划、**转入数**、已录取数、**计划余额** |
| `plan_batch4` | 第四批计划 | 初始计划、**计划余额** |
| `score_line` | 梯度线 / 控制线 | 梯度序号、分数下限 |
| `admission_result` | 录取结果留档 | 学生、批次、高中、志愿序号 |
| `quota_transfer_log` | 结转流水 | 来源批次、高中、数量、目标批次 |

## 关键约束提醒

1. `student.是否已录取` 与各 `plan_batch*.计划余额` 是同一业务事实的多处投影，
   更新必须在**同一个事务**内完成。
2. 排序键统一为：`总分 DESC, 同分排位 ASC`。
3. 第一批、第二批结束后**立即**结转余额至第三批，并写入 `quota_transfer_log`。
